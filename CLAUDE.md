# Vols à Lille-Lesquin

Petite application web mobile qui affiche les départs et les arrivées de l'aéroport de Lille-Lesquin, d'après les horaires publiés par l'aéroport. Tout est en français.

## Fichiers

- `index.html` : toute l'application (HTML, CSS et JavaScript dans un seul fichier, sans bibliothèque ; seules les polices viennent de Google Fonts : Fredoka pour les titres et les heures, Atkinson Hyperlegible pour le texte, avec repli sur les polices du téléphone).
- `historique.gs` : script Google Apps Script qui alimente l'historique (voir « Historique »). Ne sert pas au site : ne pas l'envoyer sur GitHub.
- `releve_manuel.gs` : deuxième fichier du même projet Apps Script (Fichiers > + > Script) : relevé manuel des vols de nuit avant Aerovision, à importer dans `Reel` (voir « Relevé manuel »). Ne pas l'envoyer sur GitHub.
- `manifest.webmanifest` et `icons/` : installation sur l'écran d'accueil (icônes 192, 512, apple-touch 180, favicon 32 : avion clair sur fond bleu `#0b5a8a`, générées avec Pillow).
- `.claude/launch.json` : serveur local de test (port 8766). Attention : `preview_start` peut lancer le serveur d'un autre projet si la session a été déplacée ; vérifier le nom renvoyé.

- Mettre à jour : dépôt > Add file > Upload files > glisser le fichier modifié > Commit changes ; le site suit en une à deux minutes.

## Fonctions

- Deux boutons « Départs » / « Arrivées » et deux boutons « Aujourd'hui » / « Demain ».
- Recherche par ville, compagnie ou numéro de vol.
- Case « Seulement les vols avec heure réelle ».
- Pour chaque vol : heure (réelle si connue, sinon prévue en grisé), ville (« Vers » / « De »), compagnie avec son logo, numéro, et pastille d'état colorée (annulé en rouge, retard en orange, décollé / atterri en vert).
- Mise à jour automatique toutes les minutes ; si la connexion est perdue, les dernières données restent affichées.
- Si « Aujourd'hui » est vide et « Demain » non, l'appli bascule seule sur « Demain » tant que l'utilisateur n'a rien choisi.
- Mode clair et mode sombre automatiques.

## Comment elle lit les données

- Source : la page `https://www.lille.aeroport.fr/infos-vols-et-compagnies/arrivees-departs/` (constante `URL_SOURCE`).
- `charger()` télécharge la page HTML avec `fetch`, `lire()` en extrait les lignes des tableaux dont les identifiants sont dans `IDS` (`depart-jour`, `depart-demain`, `arrivees-jour`, `arrivees-demain`). La date vient des titres `titre-date-…`.
- Colonnes attendues dans chaque ligne : heure prévue, numéro de vol, compagnie (logo), ville, statut.
- L'heure réelle est l'heure lue dans le statut quand celui-ci est « constaté » (Décollé, Atterri…), pas quand il dit « Prévu à » ou « Estimé ».
- **Téléphones** : le site de l'aéroport redirige les navigateurs mobiles vers `/mobile/vols.php`, dont les identifiants sont différents (`today-departures`, `tomorrow-departures`, `today-arrivals`, `tomorrow-arrivals`, dates dans `data-today` / `data-tomorrow` de `#display-date`, pas de logos). `lire()` gère les deux pages (`IDS` et `IDS_MOBILE`). Constaté le 26/09/2026 : sans cela, « Impossible de lire les horaires » sur téléphone seulement.
- Fragile : si l'aéroport change la structure de sa page (identifiants, colonnes), la lecture cesse de marcher et l'appli affiche « Impossible de lire les horaires ». Il faudra alors adapter `lire()`.
- CORS : l'aéroport autorise les lectures depuis un autre domaine (`Access-Control-Allow-Origin: *`, vérifié le 26/09/2026). À revérifier si l'appli cesse de charger.

## Historique : vols réels (Aerovision) et théoriques

Objectif : garder jour après jour les vols réellement décollés ou atterris et les comparer aux horaires prévus.

- **Vols réels** : Aerovision (`https://lfqq.aerovision.cloud/appmap`), le système de suivi du bruit de l'aéroport (Acoem). Données radar du contrôle aérien du Nord, retardées de 30 minutes, corrigées à J+1, trafic commercial de Lille seulement. Ce n'est pas une API prévue pour être réutilisée : un accès officiel serait préférable.
- **Comment on les lit** (serveur `https://server.lfqq.aerovision.cloud`, en-tête `Abp.TenantId: 1`) : `POST /api/TokenAuth/PublicAuthentication?language=fr` donne un jeton public (rôle « Public Unregistered », sans identifiant) ; `POST /api/services/app/Flight/SearchFlightIds` (corps : `dateRanges` en UTC, `filters: []`, `timeTrackSelectionMode: 0`, `isSmoothedPlots: true`, etc.) renvoie des identifiants ; `GET /api/services/app/Flight/GetFlightsById?ids=…&ids=…` donne le détail (`direction` DEP/ARR, `firstPlotTimeStamp`, `callSign`, `aircraftOperatorIcao`, `aircraftModelIcao`, `fromIcao`, `toIcao`). Vérifié le 26/09/2026 avec FPO443 (Lille vers Alger, B738, 07:53). Le champ `runway` est toujours vide : la piste est déduite (voir « Piste »).
- **Rapprochement** : Aerovision donne l'indicatif radar et la compagnie en code ICAO ; l'aéroport donne le numéro commercial et le logo, dont le nom de fichier est le code ICAO de la compagnie (`…/logos/FPO.jpg`). `comparerJour` associe par sens, compagnie et heure la plus proche (90 minutes au plus). Imparfait : à surveiller.
- **Le théorique ne se rattrape pas** : la page de l'aéroport ne montre qu'aujourd'hui et demain, donc l'historique de comparaison ne commence qu'au premier passage du script.
- **Stockage** : un Google Sheets (feuilles `Reel`, `Theorique`, `Comparaison`), créé à la main ; le script y est attaché (Extensions > Apps Script). Le classeur est réservé à l'organisatrice.
- **Installation** (à faire une fois) : coller `historique.gs` dans l'éditeur ; lancer `testerTheorique`, `testerReel`, `testerComparaison` (autoriser l'accès demandé) ; lancer `installerDeclencheurs` (passage toutes les heures pour le théorique, à 4 h pour les vols réels d'hier) ; Déployer > Application Web, exécuter en tant que « Moi », accès « Tout le monde » ; coller l'adresse (elle finit par `/exec`) dans `HISTORIQUE_URL` de `index.html`. Après toute modification du script : Déployer > Gérer les déploiements > crayon > Nouvelle version (jamais « Nouveau déploiement », l'adresse changerait). Fuseau du projet à régler sur Europe/Paris (Paramètres du projet).
- **Pages de l'appli** : deux pavés bien séparés, choisis par deux grandes tuiles en haut. « En direct » (bleu ; site de l'aéroport). « Historique et comparaison » (violet), avec deux onglets : « Historique » (vols réels : toutes les colonnes de la feuille `Reel`, avec le nom des aéroports et des compagnies) et « Comparaison » (prévu contre réel, avec statistiques : vols prévus, vus, retards et pourcentage, écart moyen et médian, plus gros retard, vols pas vus ou non prévus ; seuil de retard au choix, 15 minutes par défaut). Dans ce pavé : plage de dates (Du / Au, raccourcis Aujourd'hui, Hier, 7 jours, Tout ; 62 jours au plus) et départs et arrivées affichés côte à côte (l'un sous l'autre sur téléphone), jour par jour. Le script sert quatre vues : `?debut=&fin=` (comparaison ; `?date=` pour un jour), `?vue=reel&debut=&fin=` (vols réels), `?vue=stats` (bilan par jour), sans paramètre (liste des jours).
- **Tout est listé** : « Historique » et « Comparaison » affichent tous les vols vus par Aerovision, sans exception (par défaut sur tout l'historique, le jour le plus récent en premier). Dans « Comparaison », un vol est rapproché d'un horaire prévu quand on en a un ; les jours d'avant le 26/09/2026 portent « Pas d'horaire prévu enregistré » (`sans_prevu`).
- **Passages automatiques** : toutes les heures, copie du site de l'aéroport et ajout des vols réels du jour (avec le retard de 30 minutes d'Aerovision) ; chaque nuit à 4 h, les vols réels de la veille sont remplacés par la version corrigée à J+1 (`capturerReel(jour, true)`).
- **Noms** : les tables `AEROPORTS` (code ICAO vers nom) et `COMPAGNIES` (code ICAO vers nom) sont dans `index.html`. Les codes absents s'affichent tels quels : compléter les tables au besoin. Pour la compagnie, on regarde d'abord le début de l'indicatif radar (les vols Volotea exploités par une autre société y sont bien « VOE »).
- **Lecture des écarts** : le radar voit le décollage (départ) ou l'atterrissage (arrivée), alors que l'horaire prévu est celui de l'aéroport : les départs paraissent donc quelques minutes en retard. Un vol « pas vu » peut être annulé ou absent des données.
- **Piste** (colonne `piste`, dernière colonne de la feuille `Reel`) : déduite des positions radar (`GET /api/services/app/Flight/GetPlotsByFlightId?flightId=…`, positions toutes les 4 s) et des pistes de Lille (`GET /api/services/app/Runways/GetCurrentActiveRunways` : 02/20 et 08/26, avec coordonnées). Arrivée : piste dans l'axe de laquelle l'avion descend (sous 250 m, à moins de 1,2 km d'une piste). Départ : la trace ne commence qu'à ~2 km de la piste, à ~500 m : on prend la piste dont l'axe et le cap correspondent le mieux. Valeurs : `26`, `20?` (incertain : départ à plus de 1 km de l'axe, souvent un virage précoce sur la 26), `-` (pas déterminée), vide (pas encore calculée). Essai du 26/09/2026 sur 30 vols : surtout piste 26, la 08 tôt le matin ; environ 10 % de `-` ou `?`. Ce n'est pas une donnée officielle. Le calcul est dans `deduirePiste` (`historique.gs`), un appel de plus par vol. `rattraperPistes` (à lancer à la main) remplit les vols déjà enregistrés, en plusieurs passages si besoin. Affichée dans « Historique » et « Comparaison » (`textePiste`) ; filtre « Piste » dans « Historique » et dans « Comparaison » (un `26?` compte comme 26 ; « Non déterminée » = `-` ou vide, et c'est là que se trouvent les vols prévus mais pas vus, qui n'ont pas de piste). Dans « Comparaison », avec un filtre, les statistiques sont recalculées dans la page à partir des vols affichés, car le bilan par jour du script ne connaît pas la piste. La référence (identifiant Aerovision) n'est plus affichée.
- **Feuille « Recap 2026 »** (`creerRecap`, à lancer une fois à la main ; ne fait rien si la feuille existe déjà : la supprimer pour la refaire) : même tableau que le fichier Excel du collectif (« Aerovision LFQQ 2026 09.xlsx », feuille « Recap 2026 ») : vols de nuit par mois, arrivées / départs / total, par tranche d'une heure de 22 h à 6 h, totaux 22-24 h, 0-6 h et général, puis par compagnie entre 0 h et 6 h (Volotea, Easyjet, Ryanair, Europe Air Poste, Air Algérie, Nouvel Air Tunisie, Oyonnair, Autres), total de l'année et part de chaque compagnie. Juin à août sont recopiés du fichier Excel (`RECAP_FIXES` : Aerovision ne permet plus de relire ces mois) ; septembre à décembre sont calculés par formules `SUMPRODUCT` sur la feuille `Reel` (clé `AAAA-MM` en colonne A ; plages ouvertes `Reel!$B$2:$B`, pas de limite de ligne fixe : une plage dépassant la taille de la feuille donne une erreur). Jour = jour du calendrier en heure de Paris ; arrivée = heure d'atterrissage, départ = heure de décollage. Compagnies reconnues au début de l'indicatif radar : VOE/VOO, EZY/EJU/EZS/EZT, RYR, FPO, DAH, LBT, OYO ; « Autres » = le reste. Vérifié le 26/09/2026 : mêmes comptes que les relevés Excel de septembre sur 4 jours sur 5 (un vol d'écart le 05/09). Le classeur Excel contient aussi les relevés jour par jour (feuilles « Juin 2026 » à « Sept 2026 », avec la piste) et un comparatif 2025 (feuille « Feuil1 » et « Juillet Oct 2025 ») : non repris.
- **Formules écrites par script** : `setFormula(s)` accepte les noms de fonctions en anglais, mais suit la langue du classeur pour les séparateurs : dans un classeur fr_FR (le nôtre), `=SUM(1,2)` donne `#ERROR!` et il faut `=SUM(1;2)`. `creerRecap` détecte le séparateur par un essai (cellule AA1 de la feuille) et convertit ses formules. Ni `setValues` ni une plage plus courte n'y changent rien (constaté le 26/09/2026 avec `testerFormules`).
- **Une feuille par année** : `creerRecap(annee)` et `creerGraphiquesRecap(annee)` (par défaut l'année en cours, heure de Paris) créent « Recap AAAA » et « Recap graphiques AAAA » (2026 garde « Recap graphiques »). 2026 = relevés Excel de juin à août + septembre à décembre calculés ; toute autre année = 12 mois calculés par formules (`moisRecap`). `verifierRecapAnnee`, appelée à chaque `passageHoraire`, crée les deux feuilles de l'année en cours au premier passage de l'année (marqueur `recap_AAAA` dans les propriétés du script : une feuille supprimée exprès n'est pas recréée). `?vue=recap&annee=AAAA` lit une année (sans `annee` : l'année en cours, sinon la dernière) et renvoie aussi la liste `annees`. Dans l'application, un menu « Année » apparaît dès qu'il y a deux feuilles ; les années lues sont gardées en mémoire (`vue.recapCache`). `NOM_RECAP` ne sert plus qu'aux fonctions de diagnostic `testerRecap` et `testerFormules` (2026).
- **Statistiques mensuelles** (troisième onglet de « Historique et comparaison », `statsOuvrir` / `statsAfficher` dans `index.html`) : lit `?vue=recap` (`lireRecap` dans `historique.gs`, qui renvoie les chiffres de la feuille « Recap 2026 » : par mois, arrivées et départs, 8 tranches horaires, 8 compagnies, totaux). Affiche : cartes (total, arrivées, départs, part de minuit à 6 h), graphique en colonnes empilées par mois (arrivées violet `--arr`, départs orange `--dep`), tableau par mois avec total, tableaux « par tranche horaire » et « par compagnie » avec petites barres. Un menu « Période » (tous les mois ou un mois) règle les deux derniers. Les mois sans vol (octobre à décembre tant qu'ils sont vides) sont masqués. Les dates du haut ne servent pas dans cet onglet (cachées). Dessin des graphiques sans bibliothèque, en HTML et CSS, avec tableaux pour la lecture à l'écran.
- **Graphiques dans le classeur** (`creerGraphiquesRecap`, à lancer une fois ; ne fait rien si la feuille « Recap graphiques » existe) : crée cette feuille avec 4 petits tableaux qui renvoient aux cellules de « Recap 2026 » (`='Recap 2026'!O7`, donc sans séparateur et valables en fr_FR) et 4 graphiques : vols de nuit par mois (colonnes empilées), par tranche horaire (barres), part des compagnies de 0 h à 6 h (camembert), compagnies par mois (colonnes empilées). Les positions du tableau viennent de `RECAP_PREMIERE` et `RECAP_PAS` ; si la disposition de « Recap 2026 » change, adapter ces deux constantes.
- **Relevé manuel** (`releve_manuel.gs`, `importerReleveManuel`, à lancer une fois ; relançable sans doublon ; `annulerReleveManuel` retire ces lignes) : 488 vols de nuit (22 h - 6 h) du 18/06 au 26/08/2026, repris des feuilles « Juin 2026 », « Juillet 2026 », « Août 2026 » du fichier Excel « Aerovision LFQQ 2026 09 ». Ajoutés à `Reel` avec un identifiant `manuel-AAAA-MM-JJ-HHMM-n`, seulement pour les dates antérieures au premier jour Aerovision de `Reel` (27/08/2026 par défaut). Correspondances : sens = colonne où figure la piste (Atterrissage = ARR, Décollage = DEP) ; piste `26` ou `08` relevée sur place (`X` du fichier = `-`) ; indicatif = N° vol ; compagnie = début du N° vol, sinon déduite du nom (table `CIE` de l'export) ; avion = Appareil ; aéroports : noms convertis en codes ICAO (une seule exception laissée en texte : « St Aubin »), l'aéroport de Lille (LFQQ) est mis du bon côté ; `compagnie_iata` vide. Les jours d'avant le 27/08 ne montrent donc que les vols de nuit : l'onglet « Historique » l'indique par une note quand des lignes `manuel-` sont affichées. Les mois de juin à août de la feuille « Recap 2026 » restent les valeurs de l'Excel (non recalculés depuis `Reel`).
- **Rattrapage** : Aerovision refuse au public les dates de plus d'un mois environ (constaté le 26/09/2026 : limite au 26/08 à 22 h UTC) ; on ne peut donc pas remonter au 01/08. `rattraperReel` (à lancer à la main) récupère les vols réels depuis `JOUR_DEBUT_RATTRAPAGE` et se relance seule toutes les 10 minutes s'il faut plus de temps. Ne pas lancer `installerDeclencheurs` pendant un rattrapage : il supprime tous les déclencheurs.
- **État** : `historique.gs` et la page « Historique » de `index.html` sont écrits mais n'ont pas encore été essayés (ni le script dans Google, ni la page). `HISTORIQUE_URL` est vide : la page affiche « pas encore branché ». Google peut aussi refuser à Apps Script l'accès à certains sites (déjà vu avec `ntfy.sh` dans un autre projet) : à vérifier avec `testerTheorique` et `testerReel`.

## Look et accessibilité

Look « ciel et piste » : en-tête bleu avec soleil, nuage et avion dessinés en SVG, bande pointillée de piste, heures en panneau d'affichage (tuile bleu nuit, chiffres jaunes, ligne de bascule ; grisée quand l'heure n'est que prévue), vols en cartes façon billet avec perforation pointillée, formes arrondies, textes chaleureux (« Parti à 06:10 (prévu à 06:00) »). Bleu pour « En direct », violet pour « Historique et comparaison ».

Les couleurs sont des variables en haut du `<style>` (bleu aéroport `#0b5a8a`, mode sombre inclus). L'appli est faite pour des personnes de tous âges, y compris âgées : texte d'au moins 16 px (18 px de base), contraste d'au moins 4,5, zones à toucher d'au moins 44 px. Vérifier ces points avant de changer le look.
